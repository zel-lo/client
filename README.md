# zello Client

zello는 회의에서 정한 작업, 담당자, PR과 변경 소식을 여러 GitHub 저장소에 걸쳐 연결하는 팀 협업툴입니다. 이 저장소는 zello의 React 클라이언트입니다.
로그인·저장소 연결·팀 작업·내가 맡은 작업·PR은 서버 API를 사용하고, 그 외 대시보드·알림·변경 소식에는 샘플 데이터가 남아 있습니다. zello는 협업툴의 서비스명이며, 도구 안에서 관리하는 개별 프로젝트와 구분합니다.

## 실행

```sh
npm ci
npm run dev
```

기본 개발 주소: http://127.0.0.1:5173
화면 이동에는 해시 라우팅을 사용합니다. 예: `http://127.0.0.1:5173/#/inbox`.

## 검증 및 빌드

```sh
npm test
npm run build
npm run preview
```

정적 빌드 결과는 `dist/`에 생성됩니다.

## 주요 화면

- 메인 소개: `/#/`, GitHub 로그인: `/#/login`, 회원가입: `/#/signup`
- 샘플 대시보드 미리보기: `/#/overview`
- 개인: 알림함, 내 작업(담당 이슈·검토 요청·내 PR)
- 팀: 전체 현황, 팀 작업, 코드 검토, 변경 소식(팀 업데이트·개발 기록)
- 관리: 빌드와 배포, 프로젝트 설정(일반·멤버·저장소 연결·동기화)

이슈·PR 작성 및 연결, 회의 정보, 알림 읽음 상태, 저장소 추가, 패치노트 편집과 설정은 브라우저의 localStorage에 저장됩니다.
GitHub OAuth는 Spring 서버 세션과 연결되어 있습니다. 이슈는 서버에 먼저 저장한 뒤 GitHub에 별도로 발행하며 PR 작성도 실제 GitHub에 반영합니다. 알림 표시·자동 웹훅 동기화·실제 배포는 후속 범위입니다.
로그인·회원가입 버튼은 서버 설정을 확인한 뒤 `/oauth2/authorization/github`로 이동합니다. 개발 시 Vite가 `/api`, `/oauth2`, `/login/oauth2`를 `http://127.0.0.1:8080`으로 프록시합니다. 기본 주소를 쓸 때 `VITE_GITHUB_AUTH_URL`은 비워도 됩니다. 백엔드의 `AUTHENTICATION.md`에 따라 App과 `.env`를 설정하고, `npm run dev -- --port 5173 --strictPort`로 실행해 `http://127.0.0.1:5173/#/login`에서 확인합니다. 성공 callback은 `/auth/callback`이며 `/api/me`로 회원을 확인합니다. 프로필에는 실제 로그인 회원과 로그아웃 버튼을 표시하고, 프로젝트 데이터는 샘플로 유지합니다. 토큰은 프론트에 저장하지 않습니다.
샘플 활동 기준일은 2026년 10월 27일이며 잔디 활동량은 별도로 생성한 시각화 데이터입니다.

## 기술 구성

브랜드 색상은 라이트 `#2F5BFF` / `#E8472B` / `#12151F` / `#F2F4F7`, 다크 `#7C9BFF` / `#FF8F78` / `#FFFFFF` / `#12151F`를 사용합니다. 공통 색상 역할은 `src/styles.css`에 정의하고, 헤더·사이드바·파비콘에 사용하는 원본 Z 로고는 `public/brand/`에 보관합니다. 테마를 바꾸면 로고와 브라우저 테마 색상도 함께 전환됩니다.

React 19, TypeScript, Vite, Tailwind CSS 4, shadcn/ui, React Router, Vitest 및 React Testing Library를 사용합니다.
가져온 shadcn/ui 컴포넌트의 MIT 라이선스는 [SHADCN-LICENSE.md](SHADCN-LICENSE.md)에 보존했습니다.

`docs/`는 로컬 기획 자료로 사용하며 Git 추적 대상에서 제외합니다.

## 실제 저장소 연결과 로그인 상태

GitHub OAuth 로그인 후 **프로젝트 설정 → 저장소 연결**에서 개인·Organization 저장소를 검색·선택·연결합니다. GitHub App 설치 화면으로 이동하거나 PAT를 입력하지 않습니다. 서버에 별도 OAuth App Client ID·Secret과 GITHUB_APP_TYPE=OAUTH 설정이 필요합니다. 로그인 때 read:user·repo·read:org 권한을 승인받으며 repo에는 읽기와 쓰기가 함께 포함됩니다. Organization 정책에 따라 관리자 승인이나 SSO가 필요할 수 있습니다.

홈과 사이드바에는 실제 사용자와 로그인 상태를 표시합니다. HttpOnly 쿠키와 서버의 MySQL 암호화 세션을 사용하며 GitHub 토큰은 localStorage에 넣지 않습니다. 팀 작업과 내가 맡은 작업은 실제 이슈 API를 사용합니다. 기존 대시보드와 검토 요청·알림 등 후속 화면에는 샘플 데이터가 남아 있습니다. 설정과 API는 서버의 AUTHENTICATION.md, REPOSITORY_CONNECTION.md를 참고하세요.

## 가입 안내와 실제 이슈

로그인 성공 후 연결된 저장소가 없으면 `/#/onboarding`으로 이동합니다. GitHub의 조직 접근 승인 페이지를 바로 열 수 있고 돌아오면 목록을 다시 확인합니다. 저장소를 선택하면 프로젝트 이름은 저장소 소유자 이름을 기본값으로 사용합니다. 기존 프로젝트에도 연결할 수 있습니다.

팀 작업 `/#/issues`는 서버의 목록·검색·상태·내 작업 필터·페이지 탐색을 사용합니다. 새 작업 등록은 기본으로 서버 저장 → GitHub 발행까지 진행합니다. 체크를 끄면 zello에만 저장하며, 이후 상세에서 발행할 수 있습니다. 새로고침·재로그인 후에도 저장한 작업이 유지되며, 보관한 작업은 복원할 수 있습니다. 회의 맥락은 서비스에만 보관하고 설명·완료 조건·담당자·우선순위 라벨을 GitHub에 발행합니다. 조회 전용 멤버의 변경은 서버와 화면 모두 차단합니다.

이슈 상세는 저장 버튼으로 한 번에 반영합니다. 수정 내용이 남아 있으면 먼저 저장해야 발행할 수 있습니다. 충돌 시 입력을 유지하고 최신 내용을 다시 확인할 수 있습니다. GitHub 발행 응답이 유실되면 상태를 다시 읽어 같은 작업의 발행 결과만 확인하며 새 이슈를 자동으로 재생성하지 않습니다.

API와 미구현 범위는 서버의 `ISSUES.md`를 참고하세요.


## 초대와 멤버 관리

프로젝트 설정 → 멤버에서 실제 멤버를 검색하고 초대 링크를 만들 수 있습니다. 권한(멤버/조회자, 소유자는 관리자 포함), 1시간~7일 유효 기간, 선택적인 GitHub 계정을 지정합니다. 원문 링크는 생성 직후 화면에서만 확인할 수 있습니다.

초대 링크는 로그인 후 원래 초대로 돌아오며, 참여 버튼을 눌러야 멤버가 됩니다. 관리자는 멤버를 내보내거나 권한을 변경할 수 있고, 소유자는 다른 활성 멤버에게 소유권을 이전할 수 있습니다. 기존 소유자는 관리자로 남습니다. 프로젝트 나가기는 과거 작업을 보존하며, 재참여에는 새 초대가 필요합니다. 일반 탭의 이름·설명도 서버에 저장됩니다.

권한별 액션, 확인 창, 버전 충돌 안내, 초대 만료/취소/계정 불일치 화면과 OAuth 복귀 경로 검증을 테스트합니다. 서버 정책/API/마이그레이션과 실환경 검증 범위는 `server/zello/COLLABORATION.md`를 참고하세요. GitHub 저장소 접근 권한은 zello 프로젝트 참여와 별도로 검증합니다. 이메일/DM 자동 발송 없이 링크를 복사해 공유합니다.


## 여러 저장소 연결과 화면 갱신

한 프로젝트에 여러 저장소를 연결할 수 있습니다. 연결 화면의 체크박스로 계정/페이지를 오가며 최대 50개를 선택하고 한 번에 연결합니다. 성공한 연결은 유지하며 실패한 저장소만 선택 상태로 남겨 재시도할 수 있습니다. 연결/접근 확인은 기존 개별 API로 수행하고, 전체 선택 처리 후 이슈/PR 수집을 프로젝트별 한 번씩 시작합니다. 이미 연결됐거나 보관된 저장소는 선택할 수 없습니다.

선택창의 일반 focus 이벤트는 저장소·프로젝트 목록을 재조회하지 않습니다. 조직 승인 후 돌아왔을 때와 사용자의 명시적 새로고침으로 갱신하며 선택은 유지합니다. 세션은 화면을 비우지 않고 30초 간격으로 중복 검사를 제한합니다. PR/이슈/멤버 목록도 갱신 시작만으로 기존 화면을 비우지 않습니다.
